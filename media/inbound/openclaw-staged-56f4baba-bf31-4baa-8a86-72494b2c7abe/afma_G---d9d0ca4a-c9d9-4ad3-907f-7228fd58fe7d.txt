Individua la causa reale: versione caricata dal servizio, interpreter/venv, path Python, file `.pyc`, working directory o deploy incoerente. Non assumere che il source file sia quello eseguito.

Aggiungi un preflight al servizio che, prima di entrare nel loop, verifichi e logghi:

Se una verifica fallisce, il servizio deve uscire senza generare ordini. Riavvia systemd solo dopo che questi controlli passano.

3. Preset immutabile per run

Il preset è oggi letto direttamente dal template. Questo non è accettabile: modificare il template non deve poter cambiare una run già attiva.

Implementa un flusso di start:

```text
preset compilato
→ validazione schema
→ snapshot Kraken read-only
→ copia immutabile del preset nel record della run
→ reset/inizializzazione paper
→ avvio systemd con run_id esplicito
```

Salva nel DB, dentro `runs.intent` oppure in una tabella `run_configs`, almeno:

```json
{
  "run_id": "...",
  "preset_version": "...",
  "target_net_equity_eur": 500.0,
  "duration_hours": 12,
  "fee_mode": "zero_fee",
```

Il loop deve leggere esclusivamente la configurazione congelata della run attiva, non il template sul filesystem.

4. Universo asset coerente con il preset

Il prompt Trader enumera ancora solo BTC/USD, ETH/USD e SOL/USD. Correggilo:

- ogni pair proposta deve passare da `normalize_pair()` e da verifica disponibilità broker prima di qualunque ordine.

5. Fee regime e report netto

La run deve usare il fee regime congelato:

- `zero_fee`: fee = 0 in broker paper, sizing e ledger;
- `kraken_standard`: fee configurate di default;
- `custom`: valori dal preset.

Slippage e funding restano separati e tracciati. Tutti i report devono esporre:

```text
gross P&L
entry fee allocated
exit fee
funding
slippage
net P&L
net P&L %
```

Il target run deve essere valutato su equity netta rispetto al regime economico scelto.
